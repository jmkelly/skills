# Quality Loop

Skill root: the directory containing this `SKILL.md` — every `scripts/...` path in this
file is relative to it (wherever the skill is installed). The repo being audited is the
current working directory; the scripts resolve the git repo root themselves.

Deterministic gates, one set per stack — same source + same tool version + same config
⇒ same result, so they are safe to run in CI and safe to drive an agent fix-loop from.
The stack is detected from the repo root: `*.sln`/`*.csproj` → .NET;
`pyproject.toml`/`setup.py`/`requirements.txt` → Python.

A gate is **red** while its queue still lists offenders (the audit exits 1); the loop
is done only when every gate is **green** (the audit exits 0, the queue empty).

| Stack | Gate | Tool | Gate rule | Queue written |
|---|---|---|---|---|
| .NET | quality | `crap4dotnet` (CRAP = complexity² × (1 − coverage) + complexity) | **CRAP < 10** per method (test project excluded) | `crap-queue.md` |
| .NET | metrics | `Dependably.CodeMetrics` over Roslyn | `.dependably` rules (MI ≥ 20, cyclomatic ≤ 25, …) | `metrics-queue.md` |
| .NET | mutation | `dotnet-stryker` | `thresholds.break` | `stryker-queue.md` |
| Python | quality | radon cc × coverage.py per-function coverage (same CRAP formula) | **CRAP < 10** per function (tests/ excluded) | `crap-queue.md` |
| Python | metrics | radon (module MI, function cc, arg count) | MI ≥ 20, cc ≤ 25, args ≤ 7 | `metrics-queue.md` |

Python has no mutation-testing gate yet (dotnet-stryker has no Python equivalent in
this skill); the loop driver simply doesn't offer `--skip stryker` for Python repos.

## Automated loop — `scripts/quality-loop.py`

```bash
python3 scripts/quality-loop.py [max-iterations] [batch-size] [--skip <audit> ...] [--dry-run]
```

- Runs the detected stack's quality + metrics every iteration (cheap gates first); for
  .NET, Stryker only in iterations where both of those are green, so a session never
  pays ~11 min while a cheaper gate is red.
- `--skip` validates against the detected stack (e.g. `--skip stryker` on a Python repo
  is an error: `available: quality, metrics`).
- Each failing iteration sends a headless implementor (`pi -p`, fresh session per pass)
  to fix the worst offenders; a one-paragraph handoff file carries context between
  passes. The session dir is unique per loop run (repo slug + start timestamp under
  `~/.pi/sessions/quality-implementor/`), so runs never leak handoff state into each
  other — queues regenerated by each audit are always the source of truth.
- `--dry-run` — audit phase only; prints the implementor brief without launching pi.
- Environment overrides: `QUALITY_MODEL` (implementor model), `QUALITY_SESSION_DIR`
  (exact session dir; default as above), `QUALITY_PI_APPROVE=0` (skip approval of `-p` runs).

## Manual two-agent procedure

1. **Verifier** (never edits code): run every audit for the detected stack, read each
   offender's source near `file:line`, diagnose the smell (god method, deep nesting,
   duplicated branches, untested paths, low MI, surviving mutants), and record a fix
   recommendation in the queues. Full role: `references/quality-verify.md`.
2. **Implementor**: fix the queue items worst-first, keep the build/tests green, then
   hand back. Full role: `references/quality-fix.md`.
3. Repeat until every gate is green (every audit exits 0, every queue empty).

## The audits

### CRAP audit (both stacks) — `scripts/dotnet/audit.py` or `scripts/python/audit.py`

```bash
python3 scripts/dotnet/audit.py                  # .NET: dotnet test + crap4dotnet (~1 min)
python3 scripts/python/audit.py                  # Python: coverage run -m pytest + radon
python3 scripts/dotnet/audit.py --skip-tests     # reuse last coverage.cobertura.xml (stale — reports an older tree)
python3 scripts/python/audit.py --skip-tests     # reuse last artifacts/coverage.json (stale — reports an older tree)
python3 scripts/dotnet/audit.py --include-tests  # also gate the test project / tests/ dir
```

.NET always runs `dotnet test` (Testcontainers Postgres, ~40–60 s); Python runs
`coverage run -m pytest -q` (needs `pip install radon coverage` plus the project's test
deps). Both write to the repo root with the **same schema**:

- `crap-report.json` — full report: `methods[]` (filePath, lineNumber, crap, complexity,
  coverage, severity, namespace) + `stats` + `warnings`
- `crap-queue.md` — markdown work queue, worst-first, with `file:line`

Exit 0 = green; exit 1 = red (work remains — expected mid-loop). The same `jq` query
works for both stacks (`.namespace` is the dotted module path for Python):

```bash
# All failing methods as TSV (crap, complexity, coverage, file:line, class.method)
jq -r '.methods[] | select(.crap >= 10)
       | [.crap, .complexity, .coverage, .filePath + ":" + (.lineNumber|tostring), .className + "." + .methodName]
       | @tsv' crap-report.json | sort -rn | column -t -s$'\t'
```

### Metrics audit — `scripts/dotnet/metrics-audit.py` (via repo) or `scripts/python/metrics-audit.py`

- **.NET metrics**: `scripts/dotnet/metrics-audit.py` is a skill-local, repo-agnostic
  audit (repo root / solution / test-project discovery — the same conventions as the
  CRAP audit); the repo carries only the policy file `.dependably` at the repo root
  (rules, excludes, grandfathered exceptions). Without one, the audit falls back to the
  skill-bundled `.dependably.default` next to it (generic thresholds, no exceptions).
  ~10 s.
- **.NET mutation**: `scripts/dotnet/stryker-audit.py` is likewise skill-local; the repo
  carries `stryker-config.json` in the test project (project under test, thresholds,
  reporters). Without one, the audit generates a default config pinned to the test
  project's single ProjectReference (or `--project <csproj>`). Generated configs always
  use an absolute csproj path — Stryker refuses to guess with multiple references and
  cannot resolve bare/relative `project` names reliably. ~11 min (skip when you need
  fast feedback).
- **Python**: `scripts/python/metrics-audit.py` (needs `pip install radon`) mirrors the
  `.dependably` rules by name and threshold; writes `metrics-report.json` +
  `metrics-queue.md` in the same shape.

## Anti-gaming rules (enforce in reviews)

- No `[ExcludeFromCodeCoverage]`, `#pragma warning disable`, `# pragma: no cover`, or
  `Debug.Assert`/no-op "tests" to fake coverage.
- Behavior must be preserved: no swallowed exceptions, removed validation, or weakened
  checks to shed branches.
- Coverage may legitimately rise via real unit/integration tests, but the primary lever
  is **reducing complexity**: extract methods/functions, guard clauses,
  table-driven/strategy patterns, move logic to services (keep controllers/pages thin
  per AGENTS.md).
- A split is only acceptable if the extracted units are cohesive; mechanical 1:1 copies
  that just shuffle lines are rejected.
- Generated code (migrations, scaffolding) is fine as-is if it already passes the gate.

## Notes

- **.NET**: `crap4dotnet` is a global tool targeting net8 while installed runtimes are
  9/10, so `scripts/dotnet/audit.py` sets `DOTNET_ROLL_FORWARD=LatestMajor`; the stryker
  audit does the same for its testhost.
- **.NET**: `Program.<Main>$` entries are the compiler-merged top-level statements of
  `Program.cs`. Fix by moving the statements into named static methods/classes (e.g., a
  `Cli` class with `RunAsync`), not by renaming.
- **.NET**: `COVERAGE_STALE` warnings (Razor-generated entries, ~71% unmatched) are known
  noise: coverage is matched by PDB sequence points; trust the per-method numbers in the
  JSON, not the warning.
- **Python**: the CRAP audit's per-function coverage counts a function's line span
  (from AST `end_lineno`) against coverage.py `executed_lines`; `# pragma: no cover`
  lines don't count against it.
- **Python**: MI is module-level — that is how radon computes it; per-function slices
  are unreliable (radon 6 zeroes Halstead volume on calls/`with`). Pin the Python tools:
  `radon`, `coverage`, plus the project's test runner (e.g. `pytest`).
